Lição 10 · Conceitos básicos

Interferência e não determinismo

Por que saldo = saldo + 5 pode dar errado quando dois comandos rodam ao mesmo tempo. Tempo estimado: 20 minutos. Esta página contém tudo o que você precisa; as marcações "slide N" indicam só de onde cada afirmação veio.

Antes de ler, tente responder de memória (não vale olhar):
  1. Quantas instruções "de verdade" executa uma atribuição como saldo = saldo + 5?
  2. Se dois comandos rodam ao mesmo tempo sobre a mesma variável, o resultado é sempre o mesmo?

Não importa acertar; o esforço de lembrar é o que fixa a resposta certa depois.

1. Sequencial é previsível

Na execução sequencial os comandos são executados um após o outro, e o resultado é sempre o mesmo. O exemplo do material: uma conta recebe um crédito de 100 e um débito de 80, e o saldo final é sempre 20.

Conta c = new Conta("12-3");
c.creditar(100);
c.debitar(80);
System.out.print(c.getSaldo());   // sempre 20

Fonte: 11-Concorrencia.pdf, slide 2.

2. Concorrente: dois comandos ao mesmo tempo

Em linguagens concorrentes, dois ou mais comandos podem ser executados ao mesmo tempo. Isso é possível de duas formas: executar cada comando em um processador diferente (paralelismo), ou dividir o tempo de um único processador entre os comandos, executando-os parte a parte.

Esse segundo ponto é a chave: os comandos normalmente não são atômicos.

Fonte: 11-Concorrencia.pdf, slides 3 e 5.

3. Um comando tem partes

Até uma atribuição simples é executada por partes. O material mostra que saldo = saldo + 5 executa de forma similar a esta sequência:

double tmp = saldo;
tmp = tmp + 5;
saldo = tmp;

Com isso, os métodos da conta ficam assim quando olhamos "por dentro". Os rótulos 1-2-3 e A-B-C são os do slide e serão usados no simulador abaixo.

void creditar(double vc) {
1  double tmpc = saldo;
2  tmpc = tmpc + vc;
3  saldo = tmpc;
}
void debitar(double vd) {
A  double tmpd = saldo;
B  tmpd = tmpd - vd;
C  saldo = tmpd;
}

Fonte: 11-Concorrencia.pdf, slides 6 e 10.

4. As partes se intercalam, e o resultado muda

Quando c.creditar(100) || c.debitar(80) executam concorrentemente, pode-se executar parte de um, parte de outro, arbitrariamente, até completar os dois. Também é possível executar o primeiro por completo e depois o segundo, ou vice-versa. A escolha é arbitrária, feita pelo interpretador.

Consequência: a execução pode gerar mais de um resultado. Isso é o não determinismo. O slide lista, para saldo inicial 0:

SequênciaResultado
1 2 3 A B C20
A B C 1 2 320
1 A 2 3 B C−80
A 1 2 B C 3100

Fonte: 11-Concorrencia.pdf, slides 7, 8, 9 e 11.

5. Isso se chama interferência

A execução de um comando pode interferir na execução de outro. As interferências ocorrem quando os comandos compartilham (concorrem) pelos mesmos recursos: atributos, variáveis etc. Resultados não desejados podem ser gerados.

Para evitar interferências indesejadas, o material diz que temos que: controlar o acesso a recursos compartilhados; proibir a realização de determinadas sequências de execução; e sincronizar as execuções (uma espera pelo término da outra). Como fazer isso em Java é a próxima lição.

Fonte: 11-Concorrencia.pdf, slides 12 e 13.

Prática 3 · Veja a interferência de verdade

O arquivo exemplo1.c da pasta tem duas threads (prog1 e prog2) que incrementam a variável global shared 100 vezes cada, com uma função delay() entre ler e gravar. Aqui está o trecho essencial (o arquivo completo tem ainda a thread prog2, idêntica a prog1, e o main que cria as duas com pthread_create e espera com pthread_join):

int shared = 0;        /* variavel compartilhada pelas threads */

void delay() {
  for (int m=0; m<=LIMIT; m++) {}
}

void prog1 (int * k) { /* prog1 sera' uma das threads */
  int j, tmp;
  for (j=1; j<=*k; j++) {       /* *k vale 100 */
    delay();
    tmp = shared;
    tmp = tmp + 1;
    delay();
    shared = tmp;
    delay();
  }
}
/* ... prog2 igual a prog1 ... */
int main (void) {
  /* cria as duas threads, cada uma com k = 100, e espera as duas terminarem */
  printf("--> %d\n", shared);
}

Responda, antes de rodar:

  1. A última linha do main imprime shared com printf("--> %d\n", shared), ou seja, a saída termina com --> seguido do valor final de shared. Se não houvesse interferência, qual número apareceria ali? (Dica: shared começa em 0, e cada uma das duas threads soma 1 a ele 100 vezes.)
  2. Quais linhas de prog1 correspondem aos passos 1, 2 e 3 do simulador?

Agora compile e rode três vezes, a partir da pasta da disciplina:

./exemplo1 | tail -1
./exemplo1 | tail -1
./exemplo1 | tail -1
