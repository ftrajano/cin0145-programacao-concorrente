Lição 4 · Modo prova · Monitores

Monitores

O mecanismo que caiu nas quatro provas: o que é, por que é melhor, e como wait(C) e signal(C) funcionam. Tempo estimado: 35 minutos. "s.N" indica a origem (05-monitores.pdf, salvo indicação).

Aquecimento, de memória:

  1. Quais são as cinco propriedades de uma solução para a exclusão mútua?
  2. Num semáforo, o que V(S) faz quando nenhum processo está esperando em S?
Ver respostas

1. Exclusão mútua; parar fora não atrapalha; sem deadlock; sem starvation; sem contenção entra com overhead mínimo (03, s.2–5). 2. Soma 1 a S (s := s + 1); o sinal fica guardado para o próximo P(S) (04, s.8).

1. Por que inventaram monitores

Semáforos (o tema da Lição 3, que vem antes desta) também resolvem exclusão mútua, mas os slides listam os problemas deles s.2:

  • as variáveis compartilhadas são globais, e o acesso a elas fica espalhado pelo programa;
  • para entender como elas são usadas, é preciso consultar o programa inteiro; a cada novo processo, é preciso verificar se ele as usa corretamente;
  • a mesma estrutura é usada para duas coisas diferentes: exclusão mútua e sincronização de condição.

2. O que é um monitor

Um monitor aplica a ideia de tipo abstrato de dados (ADT): os dados ficam escondidos e só são manipulados pelas operações que o tipo oferece. Dados e operações ficam num único lugar. s.3–4

monitor Nome {
   dados compartilhados        ← ninguém de fora mexe direto
   variáveis de condição
   procedimento 1 { ... }      ← processos só interagem chamando estes
   procedimento 2 { ... }
}

As duas regras que fazem dele um mecanismo de concorrência s.6, 12:

NecessidadeComo o monitor resolve
Exclusão mútuaimplícita entre os procedimentos do monitor: só um processo executa dentro do monitor por vez, sem o programador escrever nada para isso
Sincronização de condição (esperar até algo ficar verdadeiro)variáveis de condição, com wait(C) e signal(C)

Vantagens, nas palavras dos slides s.5–7. Esta lista responde à questão 3 de 2026-1 e à parte "monitores" de várias dissertativas:

  • processos interagem apenas através de chamadas aos procedimentos do monitor;
  • o monitor estará correto independentemente do número de processos que o usam; dá para ignorar como e onde os procedimentos são chamados;
  • exclusão mútua implícita entre os procedimentos;
  • podem ser implementados eficientemente;
  • permitem o desenvolvimento por equipes independentes dos processos e dos monitores;
  • facilitam o desenvolvimento e o entendimento dos programas concorrentes.

3. As operações sobre variáveis de condição

OperaçãoO que faz
wait(C)suspende o processo numa fila FIFO associada a C, e libera a exclusão mútuas.12
signal(C)se a fila de C não está vazia, acorda o processo do início da fila; caso contrário, não faz nadas.12
empty(C)verdadeiro se a fila de C está vazias.12
signal_all(C)acorda todos os processos suspensos em Cs.14
wait(C, rank)como wait, mas os processos são acordados em ordem crescente de rank (minrank(C) retorna o rank do primeiro da fila)s.14

Guarde o detalhe de signal: com a fila vazia, o sinal se perde. Ele não fica guardado para quem chegar depois. É o contrário do V(S) da Lição 3, que sempre soma 1 a S (seção 5).

Os slides dizem que signal_all, wait com rank e minrank são "disponíveis (às vezes)" (s.13–14).

4. Exemplo resolvido: produtor-consumidor

Um buffer com N posições. O produtor coloca itens (Append), o consumidor tira (Take). Quem coloca num buffer cheio espera; quem tira de um buffer vazio espera. Primeiro, o monitor s.8–9:

monitor Producer_Consumer_Monitor {
  int B[0..N-1];
  int In_Ptr = 0;  int Out_Ptr = 0;  int Count = 0;
  Condition Not_Full, Not_Empty;

  void Append(int I) {                      void Take(int I) {
p1  while (Count == N) {wait(Not_Full)};    c1  while (Count == 0) {wait(Not_Empty)};
p2  B[In_Ptr] = I;                          c2  I = B[Out_Ptr];
p3  Count = Count + 1;                      c3  Count = Count - 1;
p4  In_Ptr = (In_Ptr + 1) % N;              c4  Out_Ptr = (Out_Ptr + 1) % N;
p5  signal(Not_Empty);                      c5  signal(Not_Full);
  }                                         }
}

O monitor sozinho não faz nada: ele só guarda o buffer e os procedimentos. Quem os chama são dois processos, que rodam ao mesmo tempo, cada um num laço infinito s.10:

Producer() {                    Consumer() {
  int I;                          int I;
  while (TRUE) {                  while (TRUE) {
    Produce(I);                     Take(I);
    Append(I);                      Consume(I);
  }                               }
}                               }
ChamadaOnde rodaO que faz
Produce(I)fora do monitorfabrica um item; pode rodar em paralelo com o consumidor
Append(I)dentro do monitorguarda o item no buffer; espera se estiver cheio
Take(I)dentro do monitortira um item do buffer; espera se estiver vazio
Consume(I)fora do monitorusa o item; pode rodar em paralelo com o produtor

O slide mostra só o corpo dos dois processos; não mostra como eles são disparados. A tabela acima é uma leitura desta lição.

A notação é a dos slides: parece C, mas monitor, Condition, wait/signal e int B[0..N-1] (um array de N posições, índices 0 a N−1) não existem em C. In_Ptr é a posição da próxima gravação, Out_Ptr a da próxima leitura, e % N faz as duas voltarem a 0 depois da última posição.

5. Monitor × semáforos

O produtor-consumidor também foi resolvido com semáforos na Lição 3 (04, s.21–23). Logo depois do código do monitor, os slides resumem as diferenças s.11–12:

SemáforosMonitor
Exclusão mútuaum semáforo para exclusão mútuaimplícita entre os procedimentos do monitor
Sincronização (buffer cheio / vazio)dois semáforos (Not_empty e Not_Full)variáveis de condição Not_Empty e Not_Full
Total3 semáforos; a mesma estrutura serve para exclusão mútua e para sincronização (s.2)exclusão mútua automática + 2 variáveis de condição

Uma diferença de comportamento que cai em prova: V(S) sempre soma 1 a S (04, s.8), então o sinal fica guardado para o próximo P(S). Já signal(C) com a fila vazia não faz nada (s.12): o sinal se perde.

Questão da prova: 2026-1, questão 3 (com resposta)

Questão 3 (1 ponto). Qual é uma das principais vantagens do uso de Monitores em comparação com Semáforos?

Resposta: "A exclusão mútua entre os procedimentos do monitor é implícita." 05, s.6 e s.11–12

Por que as outras estão erradas:

  • "Variáveis de condição eliminam a sinalização": é o contrário, elas são a sinalização (signal(C)).
  • "Operam com memória distribuída": monitores são para processos que compartilham memória; sem memória compartilhada usa-se troca de mensagens (07, s.2–3).
  • "Vários processos na seção crítica ao mesmo tempo": isso violaria a exclusão mútua.

Prática 3 · Quiz de memória

Questão da prova: Prova 3, questão 1 (com resposta)

Prova 3, questão 1 (2,5 pontos). O que é o problema da exclusão mútua? Quando precisamos nos preocupar com ele? Como ele é resolvido através de Monitores?

Provas-Concorrencia-antigas.pdf, Prova 3. Junta a lição 1 com esta.

Resposta modelo (construída só com o material)

O problema. Temos N processos, cada um executando em laço uma seção não crítica e uma seção crítica. O problema da exclusão mútua é garantir que instruções das seções críticas de dois ou mais processos não sejam executadas ao mesmo tempo (03, s.2). A solução também não pode entrar em deadlock nem causar starvation, e um processo que para fora da seção crítica não pode atrapalhar os outros (03, s.4–5).

Quando nos preocupar. Sempre que processos compartilham recursos, como variáveis ou atributos. Os comandos não são atômicos e as suas partes se intercalam de forma arbitrária, então um comando pode interferir no outro e gerar resultados não desejados (11, s.5, 9, 12). Exemplo: creditar(100) e debitar(80) executados ao mesmo tempo na mesma conta podem deixar o saldo em −80 ou 100 em vez de 20.

Com monitores. Os dados compartilhados e as operações sobre eles ficam encapsulados num monitor, como num tipo abstrato de dados; os processos só interagem chamando os procedimentos do monitor (05, s.3–5). A exclusão mútua entre esses procedimentos é implícita: só um processo executa dentro do monitor por vez, e o programador não precisa escrever pré e pós-protocolo (05, s.6). Quando um processo precisa esperar uma condição, usam-se variáveis de condição: wait(C) suspende o processo numa fila FIFO associada a C e libera a exclusão mútua; signal(C) acorda o primeiro processo da fila, ou não faz nada se ela estiver vazia (05, s.12). No produtor-consumidor, por exemplo, Append espera em Not_Full quando o buffer está cheio e Take faz signal(Not_Full) depois de retirar um item (05, s.8–9).
