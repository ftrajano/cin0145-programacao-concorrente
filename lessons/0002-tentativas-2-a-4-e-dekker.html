Obriga os processos a alternar: se um para na seção não crítica, o outro não consegue mais entrar (s.9). Os slides observam que esse revezamento obrigatório é o comportamento de corrotinas, usadas em várias linguagens (Python, JavaScript, Go, Kotlin…) (s.9–10).

1. A ideia nova: uma variável para cada processo

O defeito da tentativa 1 era a variável Turn ser compartilhada: só o outro podia devolver a vez. A partir da tentativa 2, cada processo tem a sua variável, C1 para P1 e C2 para P2 s.11–12:

ValorSignificado
Ci = 1Pi está fora: não quer entrar
Ci = 0Pi quer entrar, ou está na seção crítica

As duas começam em 1. Cada processo só escreve na sua variável e só lê a do outro.

A tabela de significado é uma leitura desta lição a partir do código e de s.16, onde C1 = 0 equivale a P1 estar no laço de espera, na seção crítica ou na linha de saída. Os slides em C escrevem int C1, C2 = 1;; use o valor da versão Ada (s.11): as duas começam em 1.

2. Tentativa 2: testa, depois avisa

a1  /* seção não crítica */       b1  /* seção não crítica */

a4  /* seção crítica */           b4  /* seção crítica */

s.12. Rótulos a1–a5/b1–b5 acrescentados por esta lição.

P1 espera enquanto P2 quer entrar (a2), depois avisa que quer entrar (a3). Parece razoável. Os slides mostram a sequência que quebra tudo s.13:

tP1P2C1C2
1a2: C2 == 0? não → sai do laço—11
2—b2: C1 == 0? não → sai do laço11
3a3: C1 = 0—01

Falha: exclusão mútua. Os dois testaram antes de qualquer um avisar. O teste (a2) e o aviso (a3) são dois passos separados, e o outro processo pode agir no meio.

3. Tentativa 3: avisa, depois testa

Conserto óbvio: inverter a2 e a3. Primeiro avisa, depois espera s.14–15.

void P1() {                       void P2() {
  while (TRUE) {                    while (TRUE) {
a1  /* seção não crítica */       b1  /* seção não crítica */
a2  C1 = 0;                       b2  C2 = 0;
a3  while (C2 == 0) {};           b3  while (C1 == 0) {};
a4  /* seção crítica */           b4  /* seção crítica */
a5  C1 = 1;                       b5  C2 = 1;
  }                                 }
}                                 }

Exclusão mútua agora vale s.16: C1 = 0 sempre que P1 está em a3, a4 ou a5, e o mesmo para P2. Para P1 passar de a3, precisa ver C2 = 1, ou seja, P2 fora. Então os dois nunca estão em a4/b4 juntos.

4. Tentativa 4: passando a vez

Para sair do deadlock, quem está esperando recua por um instante: volta sua variável para 1 e logo para 0, dando ao outro uma chance de passar s.18–19.

void P1() {                       void P2() {
  while (TRUE) {                    while (TRUE) {
a1  /* seção não crítica */       b1  /* seção não crítica */
a2  C1 = 0;                       b2  C2 = 0;
a3  while (C2 == 0) {             b3  while (C1 == 0) {
a4    C1 = 1; C1 = 0;             b4    C2 = 1; C2 = 0;
    };                                };
a5  /* seção crítica */           b5  /* seção crítica */
a6  C1 = 1;                       b6  C2 = 1;
  }                                 }
}                                 }

Um processo pode sofrer starvation s.20. A sequência do slide:

tP1P2C1C2
1a2: C1 = 0—01
2—b2: C2 = 000
3—b3: C1 == 0? sim → b4: C2 = 1 (recua)01
4a3: C2 == 0? não → a5: seção crítica; a6: C1 = 1; a1; a2: C1 = 0(ainda no meio de b4)01
5—b4: C2 = 000
6volta para t3: P2 testa, encontra C1 = 0, recua… e P1 sempre passa enquanto P2 está recuado

P1 entra muitas vezes; P2 nunca. Starvation de P2.

E pode haver livelock s.21. Os slides diferenciam:

Definição do slide
Deadlocknenhuma sequência resulta em sucesso
Livelockexiste uma ou mais sequências que evitam que os processos entrem na região crítica

Na tentativa 4, a sequência ruim é os dois andarem perfeitamente juntos: os dois zeram, os dois testam e veem 0, os dois recuam para 1, os dois voltam a 0, os dois testam de novo… Os dois continuam executando, mas nenhum entra. Basta um sair desse compasso para alguém entrar. Por isso não é deadlock: existe saída, mas existe também uma sequência que nunca chega lá.

A sequência "em compasso" foi montada para esta lição a partir da definição de s.21; o slide não a escreve.

5. Algoritmo de Dekker: insistir ou recuar, decidido por Turn

Dekker junta as duas ideias: as variáveis C1/C2 das tentativas 2–4 e a variável Turn da tentativa 1. Quando os dois querem entrar, Turn decide quem recua s.22–23.

int C1 = 1, C2 = 1;
int Turn = 1;
void P1() {                          void P2() {
  while (TRUE) {                       while (TRUE) {
a1  /* seção não crítica */          b1  /* seção não crítica */
a2  C1 = 0;                          b2  C2 = 0;
a3  while (C2 != 1) {                b3  while (C1 != 1) {
a4    if (Turn == 2) {               b4    if (Turn == 1) {
a5      C1 = 1;                      b5      C2 = 1;
a6      while (Turn != 1) {};        b6      while (Turn != 2) {};
a7      C1 = 0;                      b7      C2 = 0;
      }                                    }
    }                                    }
a8  /* seção crítica */              b8  /* seção crítica */
a9  C1 = 1; Turn = 2;                b9  C2 = 1; Turn = 1;
  }                                    }
}                                    }

Lendo o pré-protocolo de P1: "aviso que quero (a2). Enquanto P2 também quiser (a3): se a vez é de P2 (a4), eu recuo (a5), espero a vez voltar para mim (a6) e aviso de novo (a7). Se a vez é minha, eu insisto e continuo testando."

Exemplo: os dois querem, com Turn = 1.

2a3: C2 != 1? sim. a4: Turn == 2? não → insiste, volta a a3b3: C1 != 1? sim. b4: Turn == 1? sim → b5: C2 = 1 (recua)011
3a3: C2 != 1? não → a8: seção críticab6: Turn != 2? sim → repete011

Ao sair, P1 passa a vez (Turn = 2). Na próxima disputa, quem recua é ele. Os slides provam a ausência de starvation em três passos s.24: se C1 = 0 e Turn = 1, em algum momento C2 será 1; se C1 = 1 e Turn = 2, em algum momento Turn será 1; logo, se P1 entra no pré-protocolo, em algum momento entra na região crítica.

7. Para mais de dois processos, e com ajuda do hardware

O resto do arquivo 03, em resumo. É o que tem menos peso nas provas.

Algoritmo da padaria s.25–27: exclusão mútua de n processos. Cada processo pega um ticket e aguarda até que o seu seja o menor. Ni = 0 quer dizer que Pi não quer entrar.

int N1 = 0, N2 = 0;
P1: N1 = 1;  N1 = N2 + 1;  while (!(N2 == 0 || N1 <= N2)) {};  /* SC */  N1 = 0;
P2: N2 = 1;  N2 = N1 + 1;  while (!(N1 == 0 || N2 <  N1)) {};  /* SC */  N2 = 0;

P1 entra se P2 não quer (N2 == 0) ou se o ticket de P1 é menor ou igual. Repare no <= de P1 e no < de P2: em caso de empate, quem passa é P1.

Exclusão mútua assistida por hardware s.28–30: o processador oferece load e store numa única instrução.

  • Test_and_Set(Li): Li := C; C := 1;. O processo repete até receber Li = 0 (C estava livre) e, ao sair da seção crítica, faz C := 0 (s.29).
  • Exchange(A, B): troca os valores de A e B. O processo repete Exchange(C, Li) até receber Li = 1 e, ao sair, troca de novo para devolver o 1 a C (s.30).

O s.26 escreve N1 :- N2 + 1; pelo s.27 (em C) é uma atribuição. O s.30 não mostra o valor inicial de C.
