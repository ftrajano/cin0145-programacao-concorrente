Semáforos: P, V e o invariante

A primeira ferramenta especial de sincronização: como P e V funcionam, como protegem a região crítica, o produtor-consumidor, os filósofos e a questão 2 de 2026-1 resolvida. Tempo estimado: 40 minutos. "s.N" indica a origem (04-semaforos1.pptx.pdf, salvo indicação).

Ver respostas

1. Testando sem parar, gastando processador: busy waiting. 2. Se um processo para fora da região crítica, o outro não consegue mais entrar (03, s.9).

1. Por que uma ferramenta nova

As tentativas do arquivo 03 usam só variáveis comuns e laços de espera. Os slides resumem os problemas desses protocolos com busy waiting s.2:

  • são difíceis de projetar, de compreender e de provar corretos;
  • são complexos;
  • as variáveis usadas para sincronizar são idênticas às outras variáveis do programa;
  • são ineficientes.

A solução: usar ferramentas especiais que ajudem a projetar protocolos corretos e que bloqueiem os processos em espera s.3. O semáforo foi uma das primeiras e é uma das mais importantes. Ele torna fácil proteger regiões críticas e também serve para sincronização de condição (esperar até algo acontecer) s.4.

2. O que é um semáforo

Um tipo abstrato de dados: um número não negativo s e duas operações s.5, 7, 8:

OperaçãoOutro nomeDefinição do slideEm palavras
P(s)wait<await (s > 0) -> s := s – 1>espera até s ser maior que 0; aí subtrai 1 e segue. Atrasa o processo até que um evento ocorra.
V(s)signal<s := s + 1>soma 1 a s, sempre. Sinaliza que um evento ocorreu.

Repare: V soma 1 mesmo que ninguém esteja esperando. O sinal fica guardado em s para o próximo P.

Tipos s.9: o semáforo genérico assume qualquer valor não negativo; o binário, só 0 ou 1.

O invariante (a ferramenta para resolver questões)

Seja init o valor inicial, nP o número de operações P completadas e nV o de V completadas s.6–7:

s = init + nV – nP        e        s ≥ 0

Juntando as duas: nP ≤ init + nV. Um P só completa se houver "saldo": o valor inicial mais os V já feitos. É isso que você vai usar na questão da prova.

3. Região crítica com semáforo

sem_t S = 1;
void Pi {
  while (TRUE) {
r1    Non_Cr_S_i;       /* seção não crítica */
r2    P(S);             /* pré-protocolo */
r3    Critical_S_i;     /* seção crítica */
r4    V(S);             /* pós-protocolo */
  }
}

s.10. Os rótulos r1–r4 foram acrescentados por esta lição para a tabela.

Passo a passo com P1 e P2. A coluna #CS é o número de processos na região crítica.

tP1P2S#CS
1r2: P(S), S = 1 > 0 → S = 0, seguer100
2r3: na região críticar2: P(S), S = 0 → espera01
3r4: V(S) → S = 1esperando S > 010
4r1completa o P(S): S = 0, entra em r301

Some S e #CS em cada linha: sempre dá 1. É assim que os slides provam as propriedades s.11–13:

  • Exclusão mútua: #CS = nP – nV e S = 1 + nV – nP, logo #CS + S = 1. Como S ≥ 0, #CS ≤ 1.
  • Sem deadlock: para os dois ficarem presos em P(S), teríamos S = 0 e #CS = 0. Mas #CS + S = 1: contradição.
  • Sem starvation (com 2 processos): se P1 está suspenso, S = 0, então pelo invariante P2 está na região crítica. Quando P2 sai, executa V(S), que acorda P1.

4. Tipos de semáforo e starvation

O que acontece com quem espera depende da implementação s.14–19:

DefiniçãoQuem espera…Starvation?
Busy-waitfica testando S num laço (o teste é atômico)pode ocorrer: P2 encontra S = 0 e fica no laço; P1 sai, volta e reentra antes de P2 testar de novo, para sempre
Blocked-seté suspenso; um sinal acorda um dos suspensos, sem ordem definidapode ocorrer com N ≥ 3: com 2 ou mais bloqueados, um deles pode ser sempre o escolhido
Blocked-queueé suspenso numa fila FIFO e acordado na ordem em que foi suspensoimpossível: no máximo N – 1 processos estão na frente

Fairness s.16: strongly-fair: se o semáforo é sinalizado infinitamente frequentemente, em algum momento todos os que esperam serão acordados. Weakly-fair: se o semáforo é mantido com valor maior que zero, em algum momento todos os que esperam serão atendidos.

5. Produtor-consumidor

Um problema de comunicação s.20. Os produtores geram dados com o procedimento Produce, que devem ser enviados aos consumidores. Os consumidores, ao receberem um dado, fazem alguma computação com o procedimento Consume. O que Produce e Consume fazem por dentro não importa: importa como o dado passa de um para o outro.

Buffer de tamanho 1 s.21. Dois semáforos: empty conta lugares livres, full conta itens guardados.

int B;
sem_t empty = 1;
sem_t full  = 0;

void Producer {                 void Consumer {
  int m;                          int m;
  while (TRUE) {                  while (TRUE) {
p1  Produce(m);                 c1  P(full);
p2  P(empty);                   c2  m = B;
p3  B = m;                      c3  V(empty);
p4  V(full);                    c4  Consume(m);
  }                               }
}                               }

Rótulos p1–p4 e c1–c4 acrescentados por esta lição.

Exemplo resolvido. O consumidor chega primeiro; o produtor produz 7 e depois 9.

tProdutorConsumidoremptyfullB
1—c1: P(full), full = 0 → espera10—
2p1: produz 7; p2: P(empty), 1 > 0 → empty = 0esperando full > 000—
3p3: B = 7; p4: V(full) → full = 1esperando017
4p1: produz 9completa c1: full = 0; c2: m = 7007
5p2: P(empty), empty = 0 → esperac3: V(empty) → empty = 1107

Em t5 o produtor não consegue gravar 9 por cima do 7 antes de o consumidor ler: empty só volta a 1 depois de c2–c3.

Buffer circular de tamanho n s.22: o mesmo esquema com um array.

int B[n];  int front = 0;  int rear = 0;
sem_t empty = n;  sem_t full = 0;

Producer:  Produce(m); P(empty); B[rear] = m;  rear = (rear + 1) % n;   V(full);
Consumer:  P(full);  m = B[front]; front = (front + 1) % n;  V(empty); Consume(m);

empty começa em n (n lugares livres). rear é a posição da próxima gravação, front a da próxima leitura, e % n faz as duas voltarem a 0 depois da última posição.

Vários produtores e consumidores s.23: dois produtores poderiam gravar ao mesmo tempo em B[rear]. Por isso o slide acrescenta mutexD (em volta da gravação) e mutexF (em volta da leitura): P(empty); P(mutexD); …; V(mutexD); V(full);.

Atenção ao slide 23. Ele declara sem_t mutexD = 0; sem_t mutexF = 0;. Pela definição de P (s.8), com valor 0 o primeiro P(mutexD) esperaria para sempre, porque nenhum V(mutexD) acontece antes. Para servir de exclusão mútua, como o S = 1 do s.10, o valor inicial teria de ser 1. Provavelmente é um erro de digitação; confirme com o professor.

6. Exclusão mútua seletiva: o jantar dos filósofos

Processos competem por acesso a conjuntos sobrepostos de variáveis compartilhadas s.24. (O outro exemplo do slide, leitores e escritores, aparece na Lição 5 com monitores.)

Cinco filósofos numa mesa redonda alternam entre pensar e comer. Cada um precisa de dois garfos para comer, e há 5 garfos, um entre cada par de filósofos. O objetivo: evitar deadlock, e outras propriedades s.25–26.

sem_t fork[4] = 1;
void Philosopher[i] {   /* filósofo 0 a 4 */
  while (TRUE) {
f1  Think;
f2  P(fork[i]);
f3  P(fork[(i+1) % 5]);
f4  Eat;
f5  V(fork[i]);
f6  V(fork[(i+1) % 5]);
  }
}

s.27, "Solução". Rótulos f1–f6 acrescentados por esta lição. O slide declara fork[4], mas usa os garfos 0 a 4, que são 5 (s.25).

O filósofo i pega primeiro o garfo i, depois o garfo (i+1) % 5. O filósofo 4 pega o 4 e depois o 0.

Prática 2 · Complete: todos com fome ao mesmo tempo

Os cinco terminam de pensar juntos, e cada um executa f2 antes de qualquer outro chegar a f3.

tO que aconteceResposta
1Filósofos 0, 1, 2, 3 e 4 executam f2: cada um pega o seu garfo i. Quantos garfos ficam com valor 0?
2Filósofo 0 executa f3: P(fork[1]). fork[1] está com o filósofo 1 →
3O mesmo acontece com 1, 2, 3 e 4. Algum filósofo chega a f4 (comer)?
4Que situação é essa?

Solução 2 s.28–29: os filósofos 0 a 3 continuam iguais, mas o filósofo 4 pega os garfos na ordem inversa: primeiro fork[0], depois fork[4].

Refaça a mesma situação: se o filósofo 0 já pegou fork[0], o filósofo 4 fica esperando já no seu primeiro P, sem segurar garfo nenhum. Então fork[4] fica livre, o filósofo 3 consegue pegá-lo como seu segundo garfo e come. Ao terminar, libera os garfos, e a cadeia anda.

Os slides mostram o código das duas soluções, mas não escrevem por que a primeira trava e a segunda não. As duas simulações acima foram feitas para esta lição, a partir do código e da definição de P (s.8).

Questão da prova: 2026-1, questão 2 (com resposta)

Questão 2 (1,8 pontos). Dados os semáforos S e Q e os trechos de código para Processo 1 e Processo 2, abaixo, que são executados concorrentemente, informe quais das sequências de chamadas a a() e b() podem ser executadas quando os semáforos forem inicializados com os valores indicados. Responda com (S) Sim ou (N) Não.

Processo 1             Processo 2
while (true) {         while (true) {
  wait(S);               wait(Q);
  a();                   b();
  signal(Q)              signal(S)
}                      }

Exemplo Prova Concorrencia 2026.pdf. wait = P e signal = V (s.5).

Resposta

SequênciaS=1 e Q=1S=1 e Q=0S=0 e Q=0
a b b a a b …SNN
a b a b a b …SSN
b a b a b a …SNN

Como chegar lá. Cada a() é precedido de wait(S) e seguido de signal(Q); cada b() é precedido de wait(Q) e seguido de signal(S). Pelo invariante (nP ≤ init + nV, s.6–7):

  • o k-ésimo a() só acontece se k ≤ S inicial + nº de b() já feitos;
  • o k-ésimo b() só acontece se k ≤ Q inicial + nº de a() já feitos.

Ou, mais simples: acompanhe S e Q chamada por chamada. a() gasta 1 de S e depois dá 1 a Q; b() gasta 1 de Q e depois dá 1 a S. Se o valor a ser gasto é 0, a chamada não pode acontecer.

Coluna S=1 e Q=1, sequência a b b a a b:

chamadagastaSQ
início11
aS (1 → 0), depois Q + 102
bQ (2 → 1), depois S + 111
bQ (1 → 0), depois S + 120
aS (2 → 1), depois Q + 111
aS (1 → 0), depois Q + 102
bQ (2 → 1), depois S + 111

Nenhuma chamada encontrou 0: S. As outras duas sequências nessa coluna também nunca encontram 0: S e S.

Coluna S=1 e Q=0:

  • a b b …: a (S 1→0, Q 0→1), b (Q 1→0, S 0→1), e o segundo b encontra Q = 0: não pode. N.
  • a b a b …: a (S→0, Q→1), b (Q→0, S→1), a (S→0, Q→1), b… nunca encontra 0. S. Com esses valores, os dois processos são obrigados a alternar.
  • b a …: o primeiro b encontra Q = 0. N.

Coluna S=0 e Q=0: o Processo 1 para no wait(S) e o Processo 2 no wait(Q); cada um espera um signal que só o outro daria. Nenhuma chamada acontece: N nas três. É um deadlock.

Estratégia montada para esta lição a partir de s.5–8. A prova não diz como o professor corrige justificativas; a tabela S/N é o que a questão pede.
